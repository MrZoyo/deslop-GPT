# `dev-v3-evidence-edges` 草案

**简体中文** · [English](README.md)

这套后续评测把 2026-09-02 一次真实项目复核中总结出的规律匿名化，整理为成对的证据边界案例。draft2 根据 2026-09-23 的 GPT-6 Sol xhigh 清理复核做了窄幅补充；draft3 再根据同日 Opus 5.5 A/B（宿主会话 xhigh）增加一组案例。当前 `dev-v3-evidence-edges-draft4` 纳入了下文的发布复核修订。它不会修改或重新计算已经冻结的 `dev-v2-focused-rc5` fixture、grader 或结果。

同一份复核也用于更新本次 Skill 规则，因此这是一套答案已暴露的开发回归集，不是证明 Skill 效果的独立留出证据。任何关于模型效果的结论都必须另用未受污染的 corpus。

## 收录内容

原始复核共整理出 19 组正反观察，统一记录在 [`evidence-bank.json`](evidence-bank.json) 中。这里的**正例**表示证据支持删除、合并或改成直接报错；**反例**表示附近看似相同的结构拥有独立依据，必须保留。

原来的七组案例覆盖其中九条观察；两组清理复核案例使草案达到九组、18 个案例。原有 19 条现场观察记录保持不变。

| 案例对 | 类别 | 正例目标 | 反例边界 |
| --- | --- | --- | --- |
| `r01` | 生产可达性 | 删除只能由测试注入标志到达的分支 | 保留由当前生产配置选择的真实变体 |
| `r02` | 路径闭合 | 退休过时 package fixture 及其私有路径 | 保留一个从当前 producer 到 consumer 的 hermetic 集成根 |
| `h01` | 测试 hermeticity | 删除依赖一次性运行产物、平时只能 skip 的测试 | 保留仓库受管的协议 fixture |
| `h02` | 测试 hermeticity | 把 builder 测试的输出从 tracked 文件改到临时目录 | 保留只读 tracked source、写临时输出的测试 |
| `v03` | 权威 artifact | 对已声明的权威 artifact 执行强制存在与校验 | 保留协议明确允许缺失的可选 enrichment |

| `s01` | Schema 契约 | 让所有当前公开 reader 都拒绝旧 schema | 保留明确用于旧版本迁移的 reader |
| `s02` | Schema 契约 | 删除关键身份字段上的历史默认值 | 保留展示字段上有文档依据的可选默认值 |

## draft2 清理复核补充

本地清理复核暴露了公开 writer 误删、manifest size 检查遗漏、修改后堆积源码否定测试，以及机械行数或词频门槛造成的误判。以下改动属于开发输入，不是新的模型成绩：

- `r02a` 增加明确的退役/修改记录和遗留的源码否定测试。两个清理不足状态分别覆盖“只删旧测试，留下旧实现”与“删旧实现，却留下证明旧实现未使用的机械测试”。`r02b` 和 `s01b` 继续保护当前集成路径与受支持的迁移行为。
- `v04a` 要求删掉私有自证代码，同时保留两个公开写入名称及 reader。两个方向的别名实现都能通过；一项合并测试或两项公开操作测试都可以接受。
- `v04b` 独立检查 size 错误/缺失、digest 错误/缺失、同长度内容损坏、两个公开 writer，以及写入/替换失败后的清理。五个破坏性状态各自仍能通过普通测试，但违反其中一个契约。
- `v04b` 的另一种有效状态把“写入前就失败”改成真正的部分写入，并在现有测试中加入同长度损坏检查。它增加七行非空代码，没有新增测试节点或哈希操作。八行预算仅适用于本例；校验器确认补强后的测试能抓住原测试漏掉的摘要和临时文件清理故障。v3 不使用 checksum 词频预算。

这些改动不回填旧分数，也不能证明模型表现已经提高。draft2 仍是答案已暴露的回归材料；比较模型前必须冻结并单独评测。

## draft3 Opus 5.5 复核补充

2026-09-23 在 checkout 之外对当时 payload 做的 Opus 5.5 A/B，在 Skill 臂观察到一种退步：在 `dev-v2-focused` 的 `v01a`、`v02a` 中，删除自证链时把全部测试一起删掉，最终没有任何可发现的测试；基线则保留了一个覆盖存活公开函数的测试。两个 `repair` 案例缺少拒绝断言，另一个采用 reader 循环，评分器未能识别。`v05` 把第一种模式做成案例对。每例每臂只运行一次，子代理有效思考档位也未独立核实，因此不能据此归因到某一句规则的因果效果。

- `v05a` 的公开函数 `render_manifest` 只有针对自证指纹与校验器的测试，契约记录了没有任何消费者读取指纹。目标要求哈希与辅助函数消失，且仍有一个测试调用 `render_manifest`。`zero_tests` 校准状态记录被拒绝的结果：行为完好、目标结构已删，但没有可发现的测试；校验器要求该状态确实发现不到测试，由剩余测试门槛负责拒绝。`insufficient_cleanup` 则保留指纹字段及其字段存在测试。
- `v05b` 代码形状相同，但契约指明一个独立发布方会重算规范化指纹并拒绝不一致的 manifest，测试固定了已发布的字面值。两个破坏性状态在普通测试保持绿色的同时删掉字段或改变规范化序列化。

这些是开发输入，不是模型成绩。draft3 仍是答案已暴露的回归材料。

## draft4 发布复核

- `h01a` 补充明确的退役契约。仅仅在局部找不到调用者，不足以删除公开函数。
- 拒绝覆盖检查接受 `assertRaises` 内对一组明确列出的 reader 进行循环调用；`s01a` 的新有效校准保留两条 reader 行为并采用这种布局。它仍是范围有限的静态检查，不能证明任意测试的覆盖程度。
- `v05a` 检查实际返回值中是否仍有指纹字段，避免因为合理说明文字提到 fingerprint 而误判。
- Skill 保留独立行为覆盖，但不强制把拒绝断言塞进成功测试，也不允许为了避免零测试而编造预期值。

历史 A/B 评分保持不变。draft4 只完成离线校准，不代表重新比较了模型效果。

## 动作与检查顺序

每个 `a` 案例要求执行 `simplify` 或 `repair`，附近的 `b` 案例负责保护边界。评分把四项判断分开：

1. **当前行为：** 合法的公开行为仍然可用。
2. **剩余测试：** 至少保留一项可发现且能够通过的测试。
3. **目标状态：** 无依据的结构已经删除，或 fail-open 契约已经修正。
4. **新增限制：** 不得新增文件、测试、依赖或抽象层；只允许动作对应的少量 Python 行数增长。唯一的单例预算是上述经过校准的 `v04b` 测试补强，其他增长仍受原门槛限制。

每个正例都有 `golden_after` 校准；每个反例都有 `destructive_mutant`。在可行时，破坏性变体仍让普通测试保持绿色，只由隐藏边界检查发现问题。草案还包含其他有效实现和故意清理不彻底的状态，用来检查评分是否依赖某个固定补丁。

## 校验草案

先运行不依赖第三方包的校验器：

```bash
python3 scripts/validate_evidence_edges_corpus.py
```

安装固定版本的评测框架后，再校验 manifest：

```bash
uv run --with agent-skill-eval==0.7.0 \
  python scripts/run_agent_skill_eval.py validate \
  evals/dev-v3-evidence-edges/evals.json
```

目前不要用这份草案比较模型。应先冻结修订版本，复核隐藏契约是否泄漏答案或绑定某个补丁形状，再重新采集 baseline。本评测的结果也不能与 `dev-v2-focused` 的小案例或小型仓库结果混算。
