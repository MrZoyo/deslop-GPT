# v0.3.2 candidate cross-version forward smoke — 2026-09-04

Status: exposed development diagnostic, not a held-out result, generalization claim, or public performance claim. Machine-readable metadata is in [`v0.3.2-candidate-cross-version-smoke-20260904.json`](v0.3.2-candidate-cross-version-smoke-20260904.json).

This release gate compared the released v0.3.1 payload with the dirty v0.3.2 candidate on four known `dev-v2-focused-rc5` cases selected before the run. Each payload received two independent runs per case, for 16 calls total. Every run used a fresh Codex collaboration subagent pinned to `gpt-5.6-sol` with `high` reasoning effort.

The agents received only an isolated two-file repository, the exact Skill payload loaded by path, and the neutral corpus prompt. They did not receive adjudication labels, graders, calibration states, other workspaces, prior results, or the parent analysis. Payload assignment was counterbalanced across repetitions, and matched payload runs were dispatched concurrently with maximum concurrency two.

## Results

| Case | Expected decision | v0.3.1 | v0.3.2 candidate |
| --- | --- | ---: | ---: |
| `t02a` | simplify duplicate private-helper coverage | 2/2 | 2/2 |
| `t02b` | preserve current and supported legacy headers | 1/2 | 2/2 |
| `f01a` | remove obsolete parser fallback | 2/2 | 2/2 |
| `f02a` | remove generic fallback value | 2/2 | 2/2 |
| **Full-case total** |  | **7/8** | **8/8** |

All 16 runs passed the remaining-test and negative-change gates. All 12 deletion-case runs passed hidden behavior and the category reduction target. The sole failure was one v0.3.1 `t02b` run: it treated the lack of a separate caller or document as evidence that the legacy-header branch was unowned, removed the branch and its positive test, and then failed the hidden compatibility contract. Both v0.3.2 runs treated the first-class positive compatibility test as a preservation root and left the behavior intact.

This is the intended directional result: the candidate improved the sensitive preservation decision without an observed loss of cleanup recall on the three paired deletion cases. With only two runs on known fixtures, it remains a release smoke rather than an effect estimate.

## Limits

- The four cases are known development fixtures, not a held-out corpus.
- Two runs per payload and case do not estimate model variance.
- This compares two Skill payloads; it has no without-Skill baseline.
- The agents loaded the Skill directly by path rather than through Codex CLI discovery.
- The collaboration host did not expose token, cost, or exact wall-time telemetry.
- These results support a narrow release decision only; they do not establish general model effect or performance.
