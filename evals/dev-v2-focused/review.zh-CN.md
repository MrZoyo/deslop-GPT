# `dev-v2-focused-rc5` 冻结前说明

**简体中文** · [English](review.md)

复核修订版：rc5 由已发布的 rc3 微案例与 rc4 微型仓库模型证据推动。它针对 `t01b`/`t03b` 的过度删除收窄 Skill 的行为保留指导，使 `v01b` 隐藏契约独立于其透传写入器，并删除导致验证微型仓库误判为阴性的词法 `envelope`/`receipt`/`proof` 缩减门槛。它没有新增评分器层、校准类型、依赖或结果机制。

## 逐案例复核

| 配对 | 删除目标 | 保留依据 | 备选有效检查 | 复核结果 |
| --- | --- | --- | --- | --- |
| `t01` | 围绕单一公开摘要的重复计数/类型/长度/None 测试 | 发布成功与空输入拒绝 | 删除案例不适用；保留形态可合并 | 行为是外部的；测试表面是独立目标 |
| `t02` | 直接测试私有辅助函数 | 当前及有文档记录的旧版头部 | 一个表驱动头部测试 | 行为不要求私有测试 |
| `t03` | 针对同一规范化 slug 的连续测试 | 空值拒绝与 Unicode casefold | 一个表驱动边界测试 | 不同边界契约保持独立 |
| `t04` | 仅测试包装渲染与透传层 | `USR/1` 外部传输格式 | 删除案例不适用；精确传输字节是依据 | 传输协议边界不是通用包装器膨胀 |
| `v01` | 本地生成的报告校验和/验证器集群 | 外部提供的工件摘要 | 备选摘要实现 | 本地自检与外部工件检查相互分离 |
| `v02` | 本地回执/重算集群 | 对照外部清单检查持久化包损坏 | 备选摘要/大小顺序 | 保留回读故障域 |
| `f01` | 当前解析器宽泛捕获后转旧行解析器 | 明确的版本 1 旧协议 | 表驱动版本案例 | 畸形当前输入会显式失败 |
| `f02` | 通用缺失名称回退 | 原子写入的部分文件清理 | 基于 `finally` 的清理实现 | 仅在清理契约具体时保留恢复逻辑 |

`a` 类案例的行为契约不要求特定测试数、测试名、辅助函数形态、缺少校验和或回退实现形态。其独立裁定阈值分别要求：至多一个充分测试、零校验和/本地验证器/哈希机制，或零回退控制流。`b` 类案例的行为契约只检查有外部意义的结果。`t03a`、`v01a` 和 `f01a` 各有一个 `insufficient_cleanup` 状态：它保留行为并移除部分目标表面，但必须无法通过缩减门槛。

`t02b` 保持不变。表明支持 `legacy_header` 的唯一独立可见迹象是现有测试名和断言；实现分支并非独立证据，隐藏裁定也不会向 agent 提供证据。这是测试夹具证据的限制，尚不能证明应新增 Skill 规则。在有针对性的后续工作之后，可以单独考虑加入一个小型可见契约文件，而不应悄然改变本修订版测试夹具。

所有 16 个微案例还应用相同的负向变更硬门槛：不得新增 Python 文件、依赖、测试、抽象、类别机制或语法错误；新增的非空 Python 正行数最多为四行。四行额度由现有表驱动保留备选方案校准。

## 微型仓库复核

### `test-bloat`

该仓库包含公开报告输出、更强的端到端断言，以及三个模拟修正周期；这些周期在四个测试类/文件中增加了计数/类型/None/长度/私有辅助函数/回归测试。反复调用确定性的 `load_records_fixture()`，可在不使用定时休眠的情况下观察测试夹具调用次数。隐藏门槛检查发布的摘要，指标则可报告测试 LOC/数量/运行时间的缩减。任何私有辅助函数都不被视为行为依据。

模型缩减门槛要求测试数、测试 LOC 和测试夹具调用次数均至少减半。已知良好的黄金版本将测试夹具调用从 19 次降至 1 次。

### `verification-bloat`

该仓库包含自生成的校验和、信封、回执、重算验证器及这些层的测试。隐藏门槛使用单独声明的摘要进行持久化回读和损坏检查，因此仅移除本地验证表演无法通过该门槛。

### `fallback-bloat`

该仓库包含重复验证、围绕当前解析的捕获、狭窄的版本化旧协议，以及原子部分文件清理。隐藏门槛要求当前和旧协议行为、可见的畸形输入失败，以及编码器失败后的清理。宽泛捕获是缩减目标；协议和清理是保留依据。

## 复核不变量

- 行为门槛与缩减目标是分开的断言；
- 微型仓库缩减指标只有在剩余测试通过后才有效；
- 未修改状态与清理不足状态不能满足缩减要求；
- 清理造成的新增内容在微案例和微型仓库运行中均为硬失败；
- 每个微型仓库都有已知良好的 `golden_after` 校准，具有类别专属指标缩减；
- `mini-evals.json` 通过现有包装器和 `compare_mini_repositories()` 后评分路径运行全部三个微型仓库；
- 每个类别至少存在两个 `alternate_valid` 覆盖（`t02/t03`、`v01/v02`、`f01/f02` 的保留变体）；
- `dev-v1` 已归档，不是当前调优目标；
- 已发布的 rc3 微案例和 rc4 微型仓库试运行保持不变，不会按 rc5 重新评分。

应先冻结 rc5，再进行有针对性的后续工作。不要将其结果与 rc3 或 rc4 合并，也不要重写历史结果工件。
