# `dev-v2-focused-rc5` 冻结前复核说明

**简体中文** · [English](review.md)

rc5 的修改依据来自已发布的 rc3 小案例和 rc4 小型仓库模型运行结果。针对 `t01b` 和 `t03b` 中的误删，它进一步明确了 Skill 应如何保留行为；`v01b` 的隐藏行为约定不再依赖只做透传的写入函数；同时删除了按 `envelope`、`receipt`、`proof` 等字面词汇计数的精简条件，因为这项条件曾让验证类小型仓库的正确结果被误判为失败。rc5 没有新增评分层级、校准类型、依赖或结果处理机制。

## 逐案例复核

| 配对 | 删除目标 | 保留依据 | 备选有效检查 | 复核结果 |
| --- | --- | --- | --- | --- |
| `t01` | 围绕同一个公开汇总结果，重复测试数量、类型、长度和 `None` | 正常发布结果，以及拒绝空输入 | 对“应删除”案例不适用；“应保留”案例中的测试可以合并 | 对外行为必须保留；冗余测试应另行精简 |
| `t02` | 直接测试私有辅助函数 | 当前格式和文档明确支持的旧版头部 | 用一项表驱动测试覆盖各类头部 | 保留行为不要求继续直接测试私有函数 |
| `t03` | 连续追加多项测试，实际都在检查同一个规范化标识符 | 拒绝空值，以及 Unicode 的 `casefold` 规则 | 用一项表驱动测试覆盖边界情况 | 两项不同的边界行为各自都有独立依据 |
| `t04` | 只覆盖包装函数的渲染测试，以及单纯透传的一层函数 | `USR/1` 对外传输格式 | 对“应删除”案例不适用；精确的传输字节就是保留依据 | 传输协议边界不能当成普通包装层删除 |
| `v01` | 本地自行生成的报表校验和与校验器 | 外部提供的文件摘要 | 另一种摘要校验实现 | 本地自检与外部文件校验分别判断 |
| `v02` | 本地生成回执并重复计算的整套机制 | 根据外部清单（manifest）检测持久化软件包是否损坏 | 调换摘要与大小的校验顺序 | 写入后回读跨越的故障边界必须保留 |
| `f01` | 当前解析器宽泛捕获异常后，退回已经过时的逐行解析器 | 明确支持的版本 1 旧协议 | 用表驱动测试覆盖不同协议版本 | 当前格式输入损坏时必须明确报错 |
| `f02` | 名称缺失时使用通用默认值 | 原子写入失败后清理未完成文件 | 使用 `finally` 实现清理 | 只有确实履行失败清理责任的恢复逻辑才保留 |

`a` 类案例的行为检查不会限定测试数量、测试名称、辅助函数结构，也不会要求代码中完全没有校验和，或采用某种特定的回退实现。另行设置的精简阈值才分别要求：最多保留一项足够的测试；校验和、本地校验器和哈希机制全部清零；或回退控制流全部清零。`b` 类案例只检查对外有意义的结果。`t03a`、`v01a` 和 `f01a` 各有一个 `insufficient_cleanup`：它能保留行为，也删掉了一部分目标代码，但必须因为清理不彻底而无法通过精简检查。

`t02b` 保持不变。Agent 能看到、且可以独立说明 `legacy_header` 仍受支持的唯一证据，是现有测试的名称和断言；实现中存在这个分支并不能反过来证明自身合理，而隐藏的人工判定也不会提供给 Agent。这说明当前测试样例的可见证据不够理想，但还不足以支撑一条新的 Skill 规则。完成后续专项验证后，可以另行考虑加入一个简短、Agent 可见的约定文件；不能在本修订版中悄悄改变样例。

全部 16 个小案例都采用同一套新增内容限制：不得新增 Python 文件、依赖、测试、抽象层、该类别中的新冗余机制或语法错误；新增的非空 Python 代码最多四行。之所以允许四行，是因为现有的表驱动保留方案需要这些代码，并不是一般性的增量预算。

## 小型仓库复核

### `test-bloat`

这个仓库有公开的报表输出和一项覆盖更完整的端到端断言，并模拟了三轮修正：四个测试类或文件中先后增加了数量、类型、`None`、长度、私有辅助函数和回归测试。`load_records_fixture()` 的结果是确定的；统计它被重复调用的次数，就能观察测试数据的重复加载，不需要靠 `sleep` 测时间。隐藏行为检查核对最终发布的汇总结果，其他指标则衡量测试代码行数、数量和运行时间减少了多少。私有辅助函数本身都不作为必须保留的行为依据。

精简检查要求测试数量、测试代码行数和样例数据加载次数都至少减半。已知正确的 `golden_after` 版本把加载次数从 19 次降到了 1 次。

### `verification-bloat`

这个仓库包含自行生成的校验和、结果封装、回执、重复计算校验器，以及专门覆盖这些层的测试。隐藏行为检查使用一份单独给出的摘要，检查写入后回读和数据损坏检测是否仍然有效。因此，只删除本地那些形式大于实效的验证，并不足以通过行为检查。

### `fallback-bloat`

这个仓库包含重复校验、包住当前格式解析的异常捕获、一项范围明确且带版本号的旧协议，以及保证原子写入的残留文件清理。隐藏行为检查要求当前协议和旧协议都正常工作，损坏输入必须明确报错，编码器失败后也必须清理残留文件。宽泛的异常捕获是精简目标；协议兼容与失败清理则有独立依据，必须保留。

## 复核中必须保持的条件

- 行为检查与精简目标由不同断言分别判断；
- 小型仓库只有在现有测试通过后，精简指标才会计入评分；
- 未经修改的原始状态和故意清理不彻底的状态都不能达到精简目标；
- 在小案例和小型仓库中，只要清理引入了禁止的新增内容，就直接判定失败；
- 每个小型仓库都有一个已知正确的 `golden_after` 校准版本，并且能达到该类别专属的精简指标；
- `mini-evals.json` 通过现有适配脚本运行三个小型仓库，评分后仍沿用 `compare_mini_repositories()`，不另建流程；
- 每个类别至少有两个 `alternate_valid` 覆盖版本，分别是 `t02/t03`、`v01/v02`、`f01/f02` 的保留方案；
- `dev-v1` 已归档，不是当前调优目标；
- 已发布的 rc3 小案例和 rc4 小型仓库试运行保持不变，不会按照 rc5 的规则重新评分。

先冻结 rc5，再开展有针对性的后续验证。rc5 的结果不能与 rc3 或 rc4 合并，也不能改写已经发布的历史结果文件。
