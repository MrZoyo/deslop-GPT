# 评估

**简体中文** · [English](evaluation.md)

评估材料用于检验 `deslop` 能否在不抹去有意义行为的前提下简化累积机制。这些是开发证据，不是模型普遍优越性的声明。

[`evals/README.zh-CN.md`](../evals/README.zh-CN.md) 是规范流程。当前语料库文档位于 [`evals/dev-v2-focused/`](../evals/dev-v2-focused/README.zh-CN.md)；本页负责导航和解释，不重复所有命令与阈值。

## 当前聚焦语料库

`dev-v2-focused` 有两个不同层次：

| 层次 | 形式 | 目的 |
| --- | --- | --- |
| 聚焦微型案例 | 8 对删除/保留案例，共 16 个案例 | 诊断测试、验证和回退簇中的语义决策 |
| 端到端微型仓库 | 3 个累积膨胀的仓库 | 衡量整个仓库的行为保留和有意义缩减 |

每个删除目标附近都有一个保留用反例。校准状态包括已知正确的清理、破坏性突变、其他有效解法以及刻意不足的清理。这既测试过度保留，也测试过度删除，而不要求代理复现某个历史补丁。

微型案例与微型仓库结果相互独立，不得合并为单一分数或描述为衡量同一层次。

## 决策顺序

只有通过安全和行为门槛后，缩减才具备资格：

1. **行为门槛：** 保留公开行为、协议、受支持兼容性、持久化、安全和清理契约。
2. **剩余测试门槛：** 保留已发现且通过的测试套件。
3. **缩减目标：** 移除足够的类别特定机制，构成有意义的简化。
4. **负向变更门槛：** 拒绝新增依赖、测试、包装器、抽象、语法错误及其他由清理引起的增长。

`Simplification Case Recall`（简化案例召回率）是案例级语义召回率，不是删除行数百分比。缩减幅度单独报告，且仅针对符合资格的状态。

## 运行规范

可比的模型运行需要：

- 冻结的 Skill 和语料库版本；
- 固定的模型、推理力度、Codex 版本和 harness 版本；
- 重复运行并记录次数、顺序、令牌成本和耗时；
- 每案例原始行为及缩减门槛；
- 未加载 Skill 且相互隔离的基线；
- 分别报告微型案例和微型仓库层次；
- 在作出广泛的公开模型效果声明前，使用留出证据。

[`scripts/run_agent_skill_eval.py`](../scripts/run_agent_skill_eval.py) 中的包装器处理固定的 `agent-skill-eval 0.7.0` 兼容边界、临时 Skill 发现、基线隔离检查以及所需的评分后钩子。请使用规范 [`evals/README.zh-CN.md`](../evals/README.zh-CN.md) 中的精确命令。

## 解释限制

- 通过语料库校验只能证明语料库一致性，不能证明模型性能。
- 试点结果仅适用于其精确冻结版本和运行配置。
- 测试夹具数量、清理前通过的测试、断言均值或原始删行数，都不能证明 Skill 有效。
- 增加或更改安全门槛，可能改变聚合断言率，却不改变模型行为。
- 本仓库不发布项目级性能分数。
- 真实世界现场试验不可替代受控基准运行。
