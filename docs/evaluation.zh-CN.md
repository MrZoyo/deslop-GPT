# 评测

**简体中文** · [English](evaluation.md)

这些评测材料用来检验：`deslop` 能否在不破坏重要行为的前提下，清除反复迭代积累下来的多余机制。它们只是开发过程中的证据，不能用来声称某个模型普遍优于其他模型。

完整的评测规则以 [`evals/README.zh-CN.md`](../evals/README.zh-CN.md) 为准。当前评测集的详细说明位于 [`evals/dev-v2-focused/`](../evals/dev-v2-focused/README.zh-CN.md)；本页只提供入口和解读指南，不再复制其中的全部命令与阈值。

## 当前专项评测集

`dev-v2-focused` 分为两个互不混算的层级：

| 层次 | 形式 | 目的 |
| --- | --- | --- |
| 专项小案例 | 8 对“应删除/应保留”案例，共 16 个 | 检查 Agent 能否正确判断测试、验证和回退逻辑该删还是该留 |
| 端到端小型仓库 | 3 个包含累积冗余的仓库 | 衡量整库清理能否保留行为并真正减少复杂度 |

每个“应删除”案例旁边都有一个相近但“应保留”的对照案例。校准样本包括已知正确的清理结果、会破坏行为的错误改法、其他同样有效的方案，以及故意清理不彻底的方案。这样既能检查 Agent 是否该删不删，也能检查它是否误删，同时不要求它照抄某个历史补丁。

小案例和小型仓库衡量的是不同层面，结果必须分开报告，不能合并成一个分数，也不能说它们测的是同一件事。

## 后续证据边界草案

[`dev-v3-evidence-edges`](../evals/dev-v3-evidence-edges/README.zh-CN.md) 是另一套独立草案，来源于 19 条匿名化现场观察。目前先完成了 7 对可执行 fixture，分别检查生产可达性、当前路径的集成根、测试输入输出是否受管、权威 artifact 是否必需、所有 schema reader 是否一致，以及关键字段是否仍有历史默认值。

当清理过程暴露 current contract 的 fail-open 缺口时，这套草案允许 `repair`，并继续区分普通的 `simplify` 与 `preserve`。由于同一份现场复核也用于更新 Skill，这里只能作为答案已暴露的开发回归证据，不能当作独立留出集。它已经具备离线正反校准，但还没有冻结后的模型 baseline，因此不属于当前定量基准，也不能与 `dev-v2-focused` 的结果混算。

## 运行时控制与发布 smoke

[`runtime-controls`](../evals/runtime-controls/README.zh-CN.md) 把默认只读行为与清理质量分开检查。三个案例通过三种调用路径到达同一份输入：显式审计、清理语气但不显式调用的请求，以及完全不要求清理的提问。它们都不授权工作树改动，也都不产生简化或保留分数。由于 harness 不产出自动的 Skill 使用信号，是否被选中要从 transcript 读取，而不是由断言判定。

[`release-smoke`](../evals/release-smoke/) 把少量前向测试绑定到精确 Skill 内容哈希。这些运行可以暴露打包、授权或明显行为回归；但由于案例已知、每项只有一次运行且没有 baseline，它们仍是开发诊断，不是模型效果证据。

## 决策顺序

只有先通过安全与行为检查，清理幅度才会计入评分：

1. **行为检查：** 对外行为、协议、仍受支持的兼容行为、持久化、安全边界和失败清理责任都必须保持不变。
2. **现有测试检查：** 清理后仍要有可识别的测试，并且测试全部通过。
3. **精简目标：** 必须移除足够多的目标机制，确实达到简化效果。
4. **新增内容限制：** 不得因为清理而增加依赖、测试、包装层、抽象层、语法错误或其他额外负担。

`Simplification Case Recall`（简化案例召回率）按案例判断是否做出了正确的语义简化，不是“删除行数百分比”。具体精简幅度另行报告，而且只统计通过前述检查的结果。

## 保证结果可比的运行要求

要让不同模型运行结果能够比较，必须做到：

- 固定 Skill 和评测集版本；
- 固定模型、推理强度、Codex 版本和评测框架版本；
- 重复运行，并记录运行次数、顺序、Token 成本和总耗时；
- 保留每个案例未经汇总的行为检查与精简检查结果；
- 使用未加载 Skill、且与其他运行相互隔离的基线；
- 分开报告小案例与小型仓库的结果；
- 在公开宣称 Skill 对模型有普遍效果之前，先取得独立留出评测的证据。

[`scripts/run_agent_skill_eval.py`](../scripts/run_agent_skill_eval.py) 负责适配固定版本的 `agent-skill-eval 0.7.0`、临时加载 Skill、检查基线隔离，以及调用必要的评分后处理。实际运行时，请严格使用 [`evals/README.zh-CN.md`](../evals/README.zh-CN.md) 给出的命令。

## 解读限制

- 通过评测集校验只能说明评测材料内部一致，不能说明模型表现好。
- 一次试运行的结果，只对当时固定的版本与运行配置有效。
- 样例数量、清理前测试是否通过、平均断言通过率或原始删行数，都不能单独证明 Skill 有效。
- 新增或修改安全检查，可能在模型行为完全不变时改变汇总后的断言通过率。
- 本仓库不发布项目级性能分数。
- 真实项目试用不能替代受控的基准评测。

## 历史材料

覆盖面较广的 `dev-v1` 套件已经退役，现存放在 [`evals/archive/dev-v1/`](../evals/archive/dev-v1/README.md)。它仍可用于回顾历史问题和参考较宽范围的安全回归，但当前 CI 不再把它当作开发基准。

已发布的试运行结果保留在各自的评测目录中。它们记录的是开发历史，不能拿来宣称不同版本之间的性能差异。

## 工具背景

评测流程参考了 [agent-skill-eval](https://github.com/tardigrde/agent-skill-eval) 和 [SkillBenchmark](https://github.com/TiesPetersen/SkillBenchmark)。提到这些项目不代表对方认可本项目，也不意味着使用不同评测集、Skill、模型或评测框架版本得到的结果可以直接比较。
