# 现场试验

**简体中文** · [English](field-trials.md)

真实世界现场试验记录了 `deslop` 应用于实际公共仓库时的情况。它们以可审查的溯源信息补充合成评估和微型评估，但属于历史案例研究，不是当前调优输入或受控基准运行。

## 方法

现场试验按以下顺序进行：

1. 将公共目标仓库冻结在精确的清理前提交。
2. 先运行只读审计。
3. 审查每项拟议变更的证据链。
4. 仅应用有当前契约、调用方、历史和边界支持的发现。
5. 记录明确的保留决定以及接受的清理。
6. 保留经过审查的补丁和人工裁决，作为仅供参考的证据。
7. 记录确切的源提交、标签、树身份、许可证、采集方法和排除项。

该方法同等重视有依据的保留决定和有依据的删除。可疑构造即使保留，也不代表遗漏了清理。

## 与 Skill 调优分离

单个仓库无法确立重复的失败模式，也不足以证明通用 Skill 规则。因此，现场试验证据与运行时载荷及当前定量语料库保持分离。

- 运行时 Skill 不得被调优为复现某次试验的审查补丁。
- 参考补丁不是黄金解；未来的有效清理在结构上可以不同。
- 不得将发现推广为基准优越性或精确率声明。
- 案例可以启发未来研究问题，但不会立即成为策略。

## 泄漏边界

每个案例都将模型可见目标与参考证据分开：

```text
case/
  input/          frozen public target repository
  reference/      reviewed patches and human adjudication
  README.md       provenance, method, and limitations
  manifest.json   machine-readable source identity
```

未来评估只能将 `input/` 实例化到 `deslop-GPT` 仓库根目录之外的隔离工作区。被评估代理获得 Skill 载荷和隔离的目标仓库，而不能获得周围案例的 README、清单、补丁、裁决或详细预期清理说明。

这是当前案例研究格式的文档边界，不是新增的评估运行器。

### cluster-gpu-monitor 的限制

首个案例具有精确的公开前后溯源信息和完整冻结的输入树，但没有来自完全相同清理前状态的独立基线运行。因此，它无法证明 Skill 击败基线、可推广到其他仓库、达到 100% 精确率或已在生产环境验证。

其价值更为有限：为审查候选精确率、证据链推理以及在行为含义不明确时保留行为提供证据。

## 添加未来案例

未来的现场试验贡献应包括：

- 公开来源及兼容许可证；
- 精确的清理前和审查后提交身份；
- 可重复采集的完整跟踪快照；
- Git 生成的审查补丁；
- 简明人工裁决，包括保留决定；
- 明确排除私有仓库、生产环境和凭据；
- 相同的 `input/` 与 `reference/` 隔离边界；
- 说明是否存在可比基线的解释章节。

不要仅为归档一个案例而添加评分器、分数、模式框架或新的 Skill 规则。
