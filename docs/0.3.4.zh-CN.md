# 0.3.4 发布说明

**简体中文** · [English](0.3.4.md)

0.3.4 是一次范围较小的规则澄清：删除本地校验，不代表可以改变仍受支持的存储表示或领域返回值。同步修改读写两端后的 round-trip 不能独立证明兼容性，应使用既有或契约定义的输入；配对示例也允许在格式明确退役时删除解码器。运行时只改动 `SKILL.md` 和已有的验证参考文件，调用方式、授权边界及必要测试修复规则不变。

评测侧独立新增 [JSON 生命周期案例](../evals/dev-v4-persistence/README.zh-CN.md)、[CSV／SQLite 跨格式案例](../evals/dev-v4-transfer/README.zh-CN.md) 和可选的[拒绝覆盖识别修订](../evals/grader-revisions/edge-coverage-v1/README.zh-CN.md)。原 rc5、draft4 输入、评分器和历史分数保持冻结。跨格式案例设计者没有看到已固定的候选技能或之前的案例和结果。

## 版本比较

2026-10-05 的本地比较使用全新上下文的 `gpt-6.1-sol` / `xhigh` 代理，固定两版 payload、输入、评分器和阈值。主分母为 192 次调用，其中旧版 mini 有 1 次无效调用，仍保留在分母中；追加的独立调用修复该隔离失败，总计 193 次调用、192 份有效输出，没有用追加结果替换主表。

| 层级 | 0.3.3 | 0.3.4 |
| --- | ---: | ---: |
| 聚焦小案例 | 40/48 | 38/48 |
| Mini 仓库 | 6/9（8 次有效） | 8/9 |
| JSON 生命周期 | 6/6 | 6/6 |
| CSV／SQLite 跨格式 | 12/12 | 12/12 |
| 证据边界 | 14/18 | 15/18 |
| 调用方明确限制的只读控制 | 3/3 | 3/3 |

结果有升有降，不能据此宣称整体更优。另行检查同一个已知 mini 案例的旧 JSON 文件读取时，结果从 0/3 改善到 3/3，旧版组包含追加调用；这是重复运行下的定点兼容性观察，不是三个独立项目的证据。历史分支删除目标、测试数量／增长预算和无效调用造成的失败均保留。少量重复的合成案例不能证明统计显著性或真实项目泛化。完整原始轨迹仍保存在维护者本地证据档案中；本页公开的是经审核的摘要，不是可独立复查的公开运行档案。

两个补充探针记录漏检问题，不倒改主比较分数：

- 对照期间发现的 [SQLite 已有版本 0 数据库探针](../evals/grader-revisions/transfer-existing-v0-v1/README.zh-CN.md) 揭示了初始案例就存在的缺陷：原始状态 0/2、旧版输出 1/6、新版输出 2/6 通过。因此，主评分里的跨格式满分不代表所有书面契约均被满足。
- 运行后新增的[旧 JSON 完整性探针](../evals/grader-revisions/persistence-legacy-integrity-v1/README.zh-CN.md) 检查损坏数据和错误摘要。独立审核发现 draft1 会漏掉提前返回的变异体；保存的 6 份受支持格式输出都通过补充探针，两组各 3/3。

离线检查及新增命令见[开发说明](development.zh-CN.md#034-补充验证)。校准通过只证明评分器在这些校准状态下的表现，不等于模型效果提升。新 manifest 不会自动为通用 harness 挂载隐藏评分器，应按各套件说明执行。

调用方控制的 audit 要明确限定为检查和回答，并在两版比较中保持相同指令；这种控制不能证明仅靠 Skill 就能执行授权边界。模型比较中按路径直接读取 payload，也不同于安装后的宿主发现。`allow_implicit_invocation: false` 保持不变。
