# 0.3.4 release notes

[简体中文](0.3.4.zh-CN.md) · **English**

0.3.4 is a narrow policy clarification. Removing local checks does not authorize changing a supported stored representation or domain return value. A writer and reader changed together cannot independently establish compatibility; use an existing or contract-defined input. A paired example permits deleting a decoder when its format is explicitly retired. The runtime change is limited to `SKILL.md` and the existing verification reference. Invocation, authorization, and the policy for necessary test repair are unchanged.

The separate evaluation additions are [JSON lifecycle cases](../evals/dev-v4-persistence/README.md), [CSV/SQLite transfer cases](../evals/dev-v4-transfer/README.md), and an opt-in [rejection-coverage recognition revision](../evals/grader-revisions/edge-coverage-v1/README.md). Original rc5/draft4 inputs, graders, and historical scores remain frozen. The new transfer cases were designed without access to the frozen candidate or prior cases/results.

## Version comparison

The local 2026-10-05 comparison used fresh `gpt-6.1-sol` / `xhigh` agents and frozen 0.3.3/0.3.4 payloads, inputs, graders, and thresholds. The primary denominator is 192 calls; one invalid old-version mini call remains in that denominator. A fresh supplementary call repaired that isolation failure, bringing the total to 193 calls and 192 valid outputs. It is not substituted into the primary table.

| Layer | 0.3.3 | 0.3.4 |
| --- | ---: | ---: |
| Focused micro | 40/48 | 38/48 |
| Mini repositories | 6/9 (8 valid) | 8/9 |
| JSON lifecycle | 6/6 | 6/6 |
| CSV/SQLite transfer | 12/12 | 12/12 |
| Evidence edges | 14/18 | 15/18 |
| Caller-enforced read-only controls | 3/3 | 3/3 |

Results are mixed and do not establish overall superiority. A separate old-JSON read diagnostic improved from 0/3 to 3/3 on repeats of one known mini fixture; the old arm includes the supplementary call. That is a targeted compatibility observation, not evidence from three independent projects. Legacy-deletion targets, test-count/growth budgets, and the invalid invocation remain visible as failures. The tiny repeated synthetic cases do not establish statistical significance or real-world generalization. The full raw trajectories remain in the maintainer's local evidence archive; this page publishes a reviewed summary, not an independently reproducible public run archive.

Two additional probes record scoring gaps without retroactively changing the comparison:

- The during-run [SQLite existing-version-0 probe](../evals/grader-revisions/transfer-existing-v0-v1/README.md) exposes a pre-existing fixture defect: original 0/2, old outputs 1/6, new outputs 2/6 passed. Primary transfer scores therefore do not prove every written contract was met.
- The post-run [legacy JSON integrity probe](../evals/grader-revisions/persistence-legacy-integrity-v1/README.md) checks legacy corruption and wrong digests. Independent review found draft1 can miss an early-return mutant; all six saved supported-case outputs passed the supplementary probe, 3/3 per arm.

Run the existing offline checks and the additional checks in [Development](development.md#additional-034-validation). Their calibration results establish grader behavior, not model effectiveness. New manifests do not automatically attach these hidden graders to a generic harness run; see each corpus's invocation instructions.

For caller-managed audits, explicitly authorize inspection and an answer only, and keep that instruction identical across compared payloads. These controls do not show that the Skill alone enforced the boundary. Direct payload loading in the comparison is also separate from installed-host discovery. `allow_implicit_invocation: false` remains unchanged.
